# Erdos_Solving

مستودع بحثي مخصص لدراسة مسائل Erdős بمساعدة الذكاء الاصطناعي، مع التركيز على **المعرفة أولاً، والبرمجيات ثانياً** وعلى قابلية التحقق وتتبع الأدلة.
Erdos_Solving = مختبر مفتوح لدراسة عملية البحث الرياضي البشري–الآلي على مسائل Erdős، من المحاولة الأولية إلى البرهان الرسمي.

## الهدف

بناء بيئة بحثية لكل مسألة تحفظ بصورة منظمة:

- نص المسألة ومصدره وسياقه.
- الحالة الرياضية الرسمية وغير الرسمية.
- الأدبيات والنتائج السابقة.
- محاولات الذكاء الاصطناعي والباحثين.
- الحسابات وcounterexamples.
- المتتاليات المرتبطة في OEIS.
- formalization في Lean عند الإمكان.
- أثر التحقق والنقد والقرارات.

## الحالة التشغيلية الحالية

> **مزامنة الحالة:** 16 أوت 2026. أساس التحقق الرياضي الحالي هو الالتزام `f1dba040aeeab6a4736ab8226a186d07fe86c4ed` وتشغيل GitHub Actions `31953021835`، وقد اجتاز `mk_all --check` مع `No update necessary` والبناء القانوني الكامل في **8754 مهمة**.

- المسألة النشطة: **Erdős #678**.
- نمط العمل: **إعادة بناء برهان Cambie (2024) وإعادة تنفيذه في Lean**، لا محاولة اكتشاف مستقلة عمياء.
- Claim 5: النطاقات الثلاثة والهوية الطبيعية النهائية متحققة آلياً تحت واجهتي البواقي الصريحتين.
- Claim 4 / D1–D3: آلية الكثافة وCRT والصناديق التطبيقية والربط المقاس بواجهتي Claim 5 متحققة آلياً.
- D4a–D4d: بُنيت المقاييس العامة `Nx,Ny` فعلياً، وأُثبتت شروط القسمة والوحدات، وعُزلت نوافذ الأوليات، وأُثبتت factorizations للمقياس الكامل، وأصبحت أدوات placement كمية ومتحققة آلياً.
- D4e: يوجد theorem حي يختار `y` أولاً ثم `x` قريباً تحته، ويثبت `x + k < y < x + gap`، ثم يمرر **نفس** الممثلين إلى هوية Claim 5 الكاملة.
- حد الفصل الأدنى يأتي من `x ≡ 1` و`y ≡ 0` modulo `claim4SmallScale`؛ وحد القرب الأعلى يأتي من نافذة البحث المتحركة.
- **D4 لم تُغلق بعد**: الالتزام الأخير هو إثبات `Claim4DependentPlacementData` لنوافذ Cambie الكمية الحادة، لا مجرد افتراضها.
- وجود الأوليات الخمس المطلوبة لكل `k` كبير يبقى dependency صريحاً لطبقة prime-density اللاحقة.
- Phase E (تقدير نسبة الـLCM ثم theorem النهائي) ما تزال مغلقة.
- حالة CI: **GREEN** على الرأس الرياضي المذكور؛ Mathlib cache مفعلة وGitHub `.lake` archive معطلة كما في إصلاح حادث القرص السابق.
- الخطوة التالية الوحيدة: تفريغ sharp `y_room`, moving `x_room`, وgeneral small-scale gap، ثم استدعاء endpoint المعتمد بهذه الثوابت قبل فتح Phase E.
